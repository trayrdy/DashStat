# LVGL 9 & LovyanGFX Performance Architecture (CYD ILI9341)

> **เป้าหมาย:** ทำ UI ลื่นไหลและประหยัดแรมบนบอร์ด ESP32 CYD (ESP32-2432S028R) โดยไม่มี PSRAM

---

## 1. การคำนวณข้อจำกัดฮาร์ดแวร์ (Hardware Bottlenecks)
- **ขนาดหน้าจอ:** 320 × 240 พิกเซล
- **สี:** RGB565 (16 บิต = 2 ไบต์ต่อพิกเซล)
- **ข้อมูลภาพเต็มจอ 1 เฟรม:** $320 \times 240 \times 2 = 153,600 \text{ ไบต์ } (\approx 150 \text{ KB})$
- **ความเร็ว SPI Bus:**
  - ที่ 40 MHz: ส่งข้อมูลได้สูงสุด $\approx 5 \text{ MB/s} \implies 5,000,000 / 153,600 \approx \mathbf{32.5 \text{ FPS}}$ (เต็มจอ)
  - ที่ 80 MHz: ส่งข้อมูลได้สูงสุด $\approx 10 \text{ MB/s} \implies 10,000,000 / 153,600 \approx \mathbf{65 \text{ FPS}}$ (เต็มจอ)
- **ข้อสรุปสำคัญ:** หากต้องการเฟรมเรตที่เสถียรและลื่นไหล ไม่ควรวาดเต็มจอทุกเฟรม แต่ต้องใช้ **Dirty-Region Update** (วาดเฉพาะส่วนที่เคลื่อนไหว เช่น ตัวเลขและกราฟ) ซึ่งมีพื้นที่เพียง 5–20% ของหน้าจอ ($7.5 - 30 \text{ KB}$) ทำให้ส่งผ่าน SPI ได้รวดเร็วแม้ใช้ Partial Buffer!

---

## 2. การจัดการ Buffer โดยปราศจาก PSRAM (Internal SRAM Only)
เนื่องจากบอร์ดมี Free Heap เพียง ~320 KB:
- **ห้ามจอง Full Framebuffer 150 KB:** เพราะจะทำให้ Free Heap เหลือไม่พอสำหรับ Bluetooth Stack
- **ขนาด Draw Buffer ที่เหมาะสม:**
  - จอง 2 Partial Buffers แบบ DMA Ping-Pong
  - ขนาดต่อ Buffer: $320 \times 16 \text{ lines} = 5,120 \text{ pixels} = 10,240 \text{ bytes } (\approx 10.24 \text{ KB})$
  - รวม 2 Buffers ใช้เพียง $\approx 20.48 \text{ KB}$ เท่านั้น!
  - ขณะที่ DMA กำลังส่ง Buffer 1 ไปยังจอผ่าน SPI, CPU Core 1 จะเรนเดอร์ Buffer 2 รอไว้ล่วงหน้าแบบ Asynchronous

## 3. สถาปัตยกรรมการเรนเดอร์ (Rendering Strategy)
```
┌────────────────────────────────────────────────────────┐
│                      LVGL Canvas                       │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 1. Static Dial & Markings (วาดครั้งเดียวตอนโหลด)  │  │
│  │    - ไม่มีการ Repaint หรือ Invalidate             │  │
│  └──────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 2. Dynamic Needle & Values (Dirty-Region Only)    │  │
│  │    - Invalidate เฉพาะกรอบสี่เหลี่ยมรอบเข็ม        │  │
│  │    - มี Animation Interpolator ให้เข็มวิ่งเนียน    │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

## 4. Interpolation & Easing สำหรับมาตรวัด
- ข้อมูลจาก OBD2 ถึงแม้จะจูนดีเลย์ต่ำสุดแล้ว ก็จะวิ่งมาด้วยความเร็วประมาณ 10–25 Hz
- ตัวควบคุม UI (Animator) จะทำ **Linear / Cubic Interpolation** ระหว่างค่าเก่ากับค่าใหม่ เพื่อให้มาตรวัดกวาดที่ระดับ **30 FPS** อย่างนุ่มนวลสบายตา
